# AgentDeck v0.15.2

发布日期：2026-10-24

v0.15.0 / v0.15.1 的应用内更新功能存在一个让它「必然失败」的缺陷：下载的是发布里
的单个 exe，却按分发 ZIP 的 SHA-256 校验，每一次下载都在校验处被丢弃。本版修复
这个缺陷，并把更新链路上几处不够稳的地方一并补齐；同时重构了「设置 → 更新」页，
新增「关于」页、会话内查找的正文高亮，以及「在其他目录继续」。

> **升级说明：** v0.15.0 与 v0.15.1 受上述缺陷影响，无法在应用内升级到本版，需要
> 手动下载一次 v0.15.2（见 GitHub Releases）。从 v0.15.2 起，应用内更新可用。

## Fixed

**应用内更新「下载必然失败」**

发布里 exe 与分发 ZIP 是两个内容不同的资产。此前的代码下载 exe，却取 ZIP 的哈希
来比对，于是每次都以「SHA-256 校验未通过」告终。现在只下载那一个 exe：优先用
GitHub 随资产给出的 `digest`（`sha256:<hex>`）校验，发布早于该字段时回退到
`SHA256SUMS` 里的同名行；大小也按发布记录核对。

**下载被固定秒数砍断**

下载此前复用了「检查更新」那个 10 秒总超时的客户端，慢链路必然在同一秒数被砍断。
下载改为不设整次请求的总超时，由 45 秒「没有任何数据到达」的停滞看门狗判定卡住；
整次下载的兜底上限由 10 分钟放宽到 30 分钟，持续有数据但低于约 35 KB/s 的链路不
再被中途砍断。

**24 小时缓存恢复出「点了必败」的结论**

缓存只存了版本号，恢复后界面显示可下载，点下去却报缺少下载地址。检查结论现在连
资产地址一起落盘；旧版本写下的缓存如实要求先重新检查。

**只退出、不重启时更新不落地到快捷方式**

文件名跟随版本时，用户只退出、不重启的路径下，退出时缺了「把启动项与快捷方式改
指向新文件」那一步，下次从快捷方式启动的仍是旧版本。现在退出时即改指向，新版本
启动时的善后再做一次（幂等）。

**界面从不渲染后端错误**

「上次退出时未能完成更新」这类后端提示此前没有任何地方显示。现在状态页会显示后端
错误与本地错误。

**快捷方式改指向的 COM 初始化**

该操作需要 COM 初始化绑定在当前 OS 线程上，此前未锁定线程，调度器一挪就静默失败
（表现为「更新成功，快捷方式还指着旧版本」）。

**只开 Windows「系统代理」的用户检查更新失败**

Go 的默认传输只读环境变量代理（`HTTPS_PROXY` 等）。只开系统代理、不设环境变量的
用户（包括代理工具的「系统代理」模式）会一直看到「无法访问 GitHub」。现在环境变量
里没有代理时读取当前用户的 Windows 系统代理（手动设置的 HTTP 代理，遵守「例外」
列表）；自动配置脚本（PAC）与 socks 代理不支持，按直连处理。环境变量里设了代理时
仍以环境变量为准。

**有新版本但暂无可下载文件时显示「已是最新版本」**

发布里有更新的版本、但暂时没有可下载并校验的安装文件（没传完，或既无 `digest`
也无 `SHA256SUMS`）时，界面此前把它显示成「已是最新版本」，同时「最新版本」一栏却
是更高的版本号。现在显示「发现新版本」，说明暂无可下载文件并提供「到发布页查看」；
该结论同样随 24 小时缓存恢复。

**取消下载的竞态**

「取消下载」所用的取消函数此前在「开始下载」之后才登记，两步之间到达的取消请求会
被误报「当前没有正在进行的下载」。现在与「正在下载」状态在同一把锁内一并登记。

**选择工作目录对话框的错误提示**

去掉了对话框错误里的 `RuntimeError:` 前缀，只留说明本身。

## Added

**设置 → 关于**

版本、开发者、源码仓库、许可证（MIT）、第三方组件说明，以及「隐私与数据」：不收集
遥测、崩溃报告或使用统计，会话数据全部保存在本机，唯一的对外请求是「检查更新」。

**在其他目录继续会话**

会话右键菜单与「继续会话」旁的下拉箭头新增「在其他目录继续…」：仅本次在所选目录
里继续，不修改会话记录，也不移动文件；「保存为此项目的位置关联」默认不勾选，不会
因一次临时选择而悄悄改掉整个项目的映射。后端的目录校验与恢复命令构造此前就已支持
（Codex 会追加 `--cd`，Cursor 因按目录查找会话而明确拒绝），本版补上入口。

## Improved

**设置 → 更新页重构**

顶部是状态头（图标、一句话结论、按钮），其下是键值信息列表（当前版本、最新版本及
发布时间、上次检查、更新方式、发布页），再往下是更新内容与「启动后自动检查」开关。
切换状态只换状态头的文字、图标与按钮；下载进度条紧贴状态头，错误与取消提示各占
一行。下载可取消（取消后回到「有新版本」并给出中性提示，不留半成品），重启前有
二次确认。窄屏下按钮换行。

**下载：断点续传、复用与清理**

下载中断（网络断开、停滞）后保留 `.part`，再次下载用 Range 从断点继续；已下载部分
先计入哈希，最终对整个文件做 SHA-256，`.part` 被改过会校验失败并丢弃。同名安装包
已在且校验通过时直接复用；其他版本遗留的安装包与 `.part` 在下次下载前清理（只认
发布产物命名，不碰目录里的其他文件）。校验失败与用户取消不留半成品。

**检查更新的下载地址校验**

正式接口返回的资产下载地址必须是 `github.com` 的 https 地址，否则不报「有新版本」。
下载由 GitHub 重定向到的 CDN 那一跳不受此限。完整性校验只能说明下载内容与发布
记录一致，不构成发布者身份证明（项目未做代码签名）。

**会话内查找**

- 查找入口改为工具栏图标按钮；关键词可一键清空；Esc、查找条最右的 × 与工具栏图标
  都能收起，收起后回到查找前的阅读位置。
- 正文里的关键词高亮（全部命中淡色、当前一处加深，使用 CSS Custom Highlight API，
  不改渲染出来的 DOM，因此不影响选中、复制与折叠）。
- 输入关键词后自动跳到当前位置之后的第一处命中；正文里选中了文字时，Ctrl+F 直接
  带入它；计数按「段」显示。
- 查找条是正文上方固定的一行（像浏览器的查找栏），命中处不会被它盖住。
- 全局搜索结果里的关键词与会话内查找使用同一种黄底高亮；从全局搜索点进某个会话时，
  会带着命中词自动打开查找条。

## Known Issues

- 系统代理只实现了手动设置的 HTTP 代理；PAC 脚本与 socks 代理按直连处理。
- 点窗口 × 退出时，已下载并登记的更新会在退出的最后一步写入（界面上有说明）。开启
  「关闭到托盘」时点 × 只是隐藏，不触发写入。
- 「在其他目录继续」对 opencode、pi、cline、kimi 等智能体的跨目录恢复行为未逐一
  验证；Claude 的 `claude --resume <会话ID>` 按官方文档可在任意目录执行，但同一会话
  ID 若在多个项目目录下都有副本，Claude 会报找不到会话。
