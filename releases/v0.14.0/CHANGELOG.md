# AgentDeck v0.14.0

发布日期：2026-10-23

新增项目位置关联：项目目录改名或迁移后，会话仍可继续。

## 背景

继续会话时，恢复目录取自会话记录里的工作目录（`cwd`）。项目在磁盘上改名或迁移后，
`cwd` 仍指向旧路径，恢复脚本因此在一个不存在的目录里启动命令行工具，会话打不开。
项目「修改显示名称」只改 AgentDeck 里的名字，与磁盘目录无关，无法解决这个问题。

## Added

- 新增项目位置关联：在 `projects.db` 中新增 `project_locations` 表
  （`lkey` 主键、`original`、`target`），保存规范化完整旧路径与实际目录的关联。
  - 按完整路径**精确匹配**，不匹配子目录，不递归追踪关联链（A→B、B→C 时 A 只得到 B）。
  - 原路径本身不规范（空、相对路径、含控制字符）时按原路径处理：这类路径不可能
    存在关联，不因此让本可恢复的会话失败。
- 项目右键菜单新增三项：
  - 「打开项目目录」：在文件管理器中打开当前有效目录（Windows `explorer`、macOS `open`、
    其他平台 `xdg-open`）。
  - 「更改项目位置…」：选择并保存关联，预填当前有效位置。
  - 「移除位置关联」：仅在该项目存在关联时显示；移除后恢复使用原项目目录。
- 继续会话与复制恢复命令共用同一套目录校验：原目录或关联目录失效时，弹出位置对话框，
  展示原项目目录、当前关联目录、实际工作目录与将执行的命令，用户可选择「仅本次使用」
  或「保存为此项目的位置关联」。
- 新建会话使用项目的有效位置；对话框内目录可编辑，并明确说明「更改目录仅用于本次
  新建会话，不保存位置关联」。保存关联后，成功提示与实际启动目录一致。
- 完整数据备份纳入 `projects.db`（`VACUUM INTO` 一致性快照），恢复时在单个事务中
  合并声明项目与位置关联，同键采用备份内容。旧备份不含该库时仍可恢复；存在该库但
  关联表结构不符则整批拒绝。

## Changed

- 恢复命令改为按有效目录**重新构造**，不再替换已有命令字符串，也不修改原始会话记录：
  - 保留 OMP profile（`omp --profile <名> --resume <id>`）。
  - Codex 跨目录恢复追加 `--cd '<目录>'`（`codex resume` 实测支持 `-C/--cd`）。
  - Windows 切换目录改为 `Set-Location -LiteralPath '…' -ErrorAction Stop`：目录不存在时
    直接终止，不在错误目录继续启动命令行工具。
- 启动终端前再次校验目录，失效则拒绝启动，不回退到其他位置。
- 终端已打开但 Codex 原生名称同步失败时，对话框与列表显示该警告并标记「终端已打开」，
  避免用户重复点击造成二次启动。

## 兼容性与限制

- **不移动文件、不修改原始会话记录、不写上游存储**：位置关联只存在于 AgentDeck 自己的
  `projects.db`。原始 `cwd` 保持不变，项目筛选与置顶仍以原项目身份为准。
- **Cursor 明确拒绝跨目录恢复**：它按目录标识查找会话，关联到别处也找不到，因此只允许
  选回原目录，或在该目录新建会话。
- **其他命令行工具的跨目录能力以工具自身为准**：关联目录不代表工具一定能找到原会话。
- **WSL 会话**保持原有行为，不支持更改项目位置。
- 旧备份（不含 `projects.db`）可正常恢复。
