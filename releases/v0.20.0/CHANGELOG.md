# AgentDeck v0.20.0

发布日期：2026-11-17

## Added

- **继续已被 Claude Code 清理的会话**。Claude Code 默认只保留约 30 天（`cleanupPeriodDays`）的会话文件，超期的会被它自己清理，此前这类会话在 AgentDeck 里只能查看。阅读区的“继续已清理的会话…”和右键菜单提供两种方式：
  - **重建后继续此会话**（推荐）：先预览目标文件与带回的内容（不写任何文件），确认后在 Claude Code 的数据目录里新建会话文件，再用 `claude --resume` 继续。永久库保存的是解析后的内容而不是原始 `.jsonl`，所以只能重建：文字原样保留，工具调用与结果转写成文字，思考内容不带回，超过 12 万字符时保留开头与最近的部分，重建的会话里带一条说明。原目录不存在时可以改选一个已有目录。完成后可选择立即在终端里继续。
  - **新开会话并带上历史**：不写 Claude 的目录，把历史整理成一份文档放在 AgentDeck 自己的数据目录（`library/handoff/`），新开一个 Claude 会话（`--add-dir` 授权读取）让它先读完再继续。不是真正的续接，历史很长时只带最近的部分。
- **Claude Code 会话保留期**（设置 > 会话）：只读地显示 Claude Code 的保留天数（`settings.json` 里的 `cleanupPeriodDays`，没设置时按默认 30 天）、7 天内到期或已到期的会话（以及 AgentDeck 是否已保存副本），并给出调大保留期的设置片段 `"cleanupPeriodDays": 365` 与复制按钮。保留期设成 0 时提示 Claude 不保存会话。AgentDeck 不会修改 Claude 的 `settings.json`。

## Changed

- 这是继“手动删除会话”之后 AgentDeck 第二处写入上游存储的功能，约束同样严格：只对 `claude`、原文件已不在（`Retained`）、非 WSL / 网关 / 导入的会话开放；会话 ID 必须是小写 UUID；预览与执行分开，token 一次性、10 分钟过期，绑定会话、目录与内容哈希，执行时重新生成并比对；**只新建、绝不覆盖**（目标已存在就拒绝），先写同目录临时文件并落盘，再用硬链接放到目标名下，写完回读比对，失败撤销；落点固定为 `<Claude 目录>/projects/<由目录名推出的文件夹>/<会话 ID>.jsonl`，文件夹名只含字母数字与 `-`；目录名超过 200 字符（Claude 会改用哈希命名）时拒绝。约束写入了 `CLAUDE.md` 的安全约定。
- 新增包 `internal/rebuild`（纯计算，不碰磁盘）与 `internal/app/rebuild_service.go`；服务接口新增 `PreviewRebuild`、`Rebuild`、`ContinueWithHistory`、`ClaudeRetention`（前端绑定已同步生成）。
- 阅读区“继续已清理的会话…”按钮的提示文字改为说明而不是无障碍名称，按钮名称就是可见文字。

## Fixed

- 设置里“允许删除导入的聊天记录”的说明还写着“重新导入同一份导出也不会回来”，改为与实际行为一致（默认不会回来，可在导入页勾选恢复）。

## Known Issues

- 重建的会话不是原文件：工具调用的 id 配对、思考内容、消息 id 无法还原；很长的会话只保留开头与最近的部分。
- 只支持 Claude Code（`claude`）：Claude Desktop、WSL、网关与导入的会话不支持。
- 会话保留期的“到期”按文件修改时间和默认 30 天估算，没有在本机观察 Claude Code 的实际清理过程；只读取用户级 `settings.json`，不读项目级或企业策略里的设置。
- 与 v0.19.x 相同：原始会话里已经变成 `�` 的内容无法恢复；恢复误删的导入会话时账号名称要与当初一致；仅 Windows。
- 未在 macOS / Linux 上构建运行。

## 升级与回退

- 不改数据库结构与配置字段，首次启动无需迁移。
- 升级：在应用内“检查更新”，或用新 exe 手动替换。
- 回退：换回上一版 exe 即可。已经重建写入 Claude 数据目录的会话文件是 Claude Code 自己的普通会话文件，回退后仍可继续使用；`library/handoff/` 里的交接文档可以自行删除。
