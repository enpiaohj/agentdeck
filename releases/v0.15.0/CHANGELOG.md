# AgentDeck v0.15.0

发布日期：2026-10-23

在线更新改为应用内安装。此前「下载到本地」只把新版本解压到数据目录，需要用户自己关闭程序、
用资源管理器替换 exe；现在下载校验后点「重启并安装」即可，AgentDeck 自己在退出时写入新版本
并重新打开。

## Added

- 设置 → 更新新增「下载并准备安装」与「重启并安装」。下载并校验通过后，更新包登记为
  「退出时落地」，点「重启并安装」会在关闭数据库、释放单实例锁之后写入新版本并重新打开。
- 也可以直接退出程序：更新同样在退出时落地，下次启动即为新版本。界面明确写出这两条路径。
- 落地完成后自动改指向：开机启动项（当前用户的 `Run` 注册项）与桌面、开始菜单、任务栏的
  快捷方式，只要指向旧文件就改指向新文件，快捷方式的参数（如 `--startup`）原样保留。
- 新增 `internal/updateinstall` 包承担落地与善后，`cmd/agentdeck-desktop` 的
  `updateInstaller` 负责与启动流程衔接。

## Changed

- 文件名跟随版本：当前程序是发布产物命名（`AgentDeck-vX.Y.Z-win-x64.exe`）时，新版本以
  它自己的产物名写到同一目录，新旧并存一次，旧文件在下次启动善后时删除。文件名被用户改过
  （如 `AgentDeck.exe`）时改为原地替换，不改动用户起的名字。
- 落地时机固定在进程退出的最后一步。正在运行的 exe 不能被覆盖，因此 `StageUpdate` 只做
  可写性检查并记下更新包，真正的写入由 `FinishUpdate` 在 `a.Close()` 之后执行（`defer`
  后进先出保证顺序）。
- 程序所在目录不可写时（例如装在 `Program Files`）在**下载阶段**就报错，并提示改到有写入
  权限的目录或到发布页手动下载——不等到退出时才失败，那时已经没有界面可以说明原因。

## Fixed

- 更新包已经位于目标路径时会被自身的安装流程删除：原实现先把临时文件改名覆盖目标，再删除
  「更新包」，两者是同一个文件。现在这种情况直接早退，不做任何搬运。
- WebView2 已把主线程初始化成 MTA 时，快捷方式改指向会静默失效：`ole.CoInitializeEx` 返回
  `RPC_E_CHANGED_MODE`，原实现把它当失败直接返回 0 且不报错，用户只会看到「更新了但快捷
  方式还是旧的」。现在 `S_FALSE` 与 `RPC_E_CHANGED_MODE` 都视为 COM 可用，后者不再调用
  `CoUninitialize`（本次并未增加初始化计数）。

## 落地失败时

- 新文件先写成 `.new` 临时名并核对大小，才改名到位；原文件先改名 `.old` 留作回滚副本。
- 失败时原文件保持可用，并留下 `.update-failed` 标记；下次启动提示一次，读后即清。
- 下次启动的善后会清除遗留的临时文件与回滚副本；文件名变过的更新则先确认启动项与快捷方式
  已改指向，再删除旧文件。

## Known Issues

- 落地只在退出时进行。更新登记之后、退出之前，用户看到的仍是当前版本。
- 程序没有代码签名，`SHA256SUMS` 校验只说明下载内容与发布清单一致，不构成发布者身份证明。
- 快捷方式改指向是尽力而为：读不到或改不了的快捷方式跳过，不影响更新本身。
