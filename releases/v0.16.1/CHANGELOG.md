# AgentDeck v0.16.1

发布日期：2026-10-27

## Fixed

- 开始菜单「所有应用」显示的是快捷方式文件名，此前只改快捷方式的目标、不改名字。更新到 v0.16.0 后，
  条目仍写着 `AgentDeck-v0.15.3-win-x64`，用户看到的就是「版本号没改全」。现在版本派生的快捷方式名会跟随
  新版本改名；用户自己起的名字（`AgentDeck.lnk`、`我的工作台.lnk` 之类）保持不变。
- 自启动项此前只在「指向上一版路径」时才被改。跨版本手工替换文件、或某次更新中断，会让它停在更早的版本名上，
  此后每次更新都比对不上、永远没人修。本机实测停在 `v0.13.0`，而该文件早已不存在——开机自启实际是坏的。
  现在启动时若发现启动项指向本产品同目录下**已不存在**的旧产物，会改指向当前版本。
- 目标已是最新、名字还停在旧版本的快捷方式会自己出现（改名失败后重试、手工换文件）。启动时按当前 exe 名
  对齐一次，这类残留自愈，不必等下一次版本变化。

## Changed

- 自愈只针对确定坏掉的项：指向本产品同目录下已不存在的旧产物。指向仍然存在的另一份副本、指向别的目录或
  别的程序名的启动项与快捷方式，一概不动。
- 同名快捷方式已存在时不覆盖——那可能是用户自己又建的一个。

## Known Issues

- 快捷方式改名后，Windows 开始菜单的固定项（如果有）不会跟着改名：固定记录按原文件名保存。
  本版未在存在固定项的环境下验证；若发现固定项失效，重新固定一次即可。
- 自愈只在程序启动时执行一次，且只修「文件已不存在」的启动项。指向仍存在的旧版本副本时保持原样（那是用户的配置）。
- 未在 macOS / Linux 上构建运行。

- `go test ./... -count=1`：28 个测试包全部通过（`exit=0`）。
- `npm test`：108 项通过；`npm run build` 与 `sync-assets.ps1`：通过。
- `govulncheck@v1.1.4`：No vulnerabilities found；`npm audit`：0 vulnerabilities。
- 新增单测覆盖：版本派生快捷方式改名、自定义名字不改、目标已最新但名字陈旧的对齐、同名不覆盖、
  启动项指向已不存在旧产物时自愈、仍存在的副本不动、别的目录/程序名不动、空值不动。
- 真机实测（隔离用户目录，造出「快捷方式名停在 v0.15.3、启动项停在 v0.13.0 且文件不存在」的坏状态后启动）：
  - 快捷方式 `AgentDeck-v0.15.3-win-x64.lnk` → `AgentDeck-v0.16.0-win-x64.lnk`，目标正确。
