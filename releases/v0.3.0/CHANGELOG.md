# AgentDeck v0.3.0

发布日期：2026-10-18。平台：Windows x64。此版本重做会话阅读区的组织方式（连续过程分组、会话内查找、阅读位置记忆），把全文索引从「每次启动整库重建」改为增量更新，并修正详情栏、列表筛选与状态条上若干处「信息说不清」的地方。

## 新增

- **全文索引改为增量更新**。此前每次启动都是 `Reset` 后整库重写：28 万段 / 1.7 GB 的索引库全量重建，期间状态栏一直停在 building，代价远大于增量。新增 `doc_sources` 表记录每个会话上次被索引时的文件大小与修改时间（`UnixNano`），两者都没变就跳过重新解析。`Add` 的语义本就是按 Key 替换，增量路径因此不需要清库。
- **消失的会话不再留下孤儿索引**。上游删除、导入库清理后，索引里对应的 doc 会在同一趟里删除，否则检索会命中一个点进去只有「原始记录不存在」的会话。删除先于状态写回，`SaveStamps` 只给索引里仍有 doc 的会话留记录，避免留下永不匹配的孤儿行。
- **全量路径写回状态**。`Reset` 会连 `doc_sources` 一起清掉，若不写回，下一次增量会因为「一条记录都没有」而重读全部会话，增量等于没建立。新增用例覆盖这一条。
- **状态条显示索引规模与进度分母**。索引规模（`Index.Totals`）与这一趟的工作量在增量下差得很远：直接报这一趟的计数会把 28 万段的库说成 4 万段。状态条与设置页改为显示库内实际规模，building 时给出分母（`n / total`），`total` 尚未算出时退化为省略号。
- **设置里的「重建索引」改为强制整库重建**（`RebuildFull`）。分词契约或脱敏规则变更后用它；日常启动与刷新走增量路径。新增 6 条用例：跳过未变会话并拾取变化、删除消失会话、保留副本永远重读、状态报规模而非这一趟的工作量、全量构建写回状态、全量构建仍然清库。
- **会话内查找**（Ctrl+F，或阅读区可见的「查找」按钮）。命中段按 `SearchInAll` 的多命中列表前后跳转（Enter / Shift+Enter），显示命中段编号与摘要；退出查找回到进入前的位置，而不是跳回页首。长段预览只显示部分内容时另有说明。
- **连续过程分组**。长会话里连续的过程段落此前逐条平铺，一份会话被切成几十个折叠条、正文被挤散。`transcriptGroups` 只把相邻且可折叠的段落并成一组，组内段落原样保留，摘要给出段数与类型计数（如「过程记录 · 8 段 · 思考 3 · 工具 5」）。分组只表示连续，不声称是完整过程——窗口边界处另行标注「可能承接相邻窗口」。
- **按会话记阅读位置**。切换会话后此前一律回到设置里的默认位置，读到一半离开再回来就丢位置。改为记住段号、页内偏移与滚动位置，仅在锚点仍可见时恢复，避免恢复到一个已经折起的段落上。
- **窗口边界说明**。页首 / 页末补相邻窗口的摘录并注明「不计入当前段数」，页末给出「继续阅读后续内容」，此前翻到边界只看到内容突然断掉。
- **长代码三段式**。长代码块默认只渲染前 12 行，展开后可看全文，再展开为不限高；此前长代码把整页撑到无法滚动阅读。
- **列表筛选可组合**。侧栏此前是「视图替换」：选了项目再点 agent 会把项目筛掉，无法「只看 Codex 在某个项目下的会话」。现在同一维度再点一次取消，不同维度叠加。
- **筛选芯片**。列表工具条新增可移除的筛选芯片（agent / 项目 / 收藏 / 归档），当前生效的筛选不必回侧栏才看得见；项目筛选生效时行内不再重复显示项目名。
- **搜索返回不再丢状态**。进入搜索结果后会话列表此前被卸载，返回时筛选、展开的子会话与滚动位置全部重置。改为搜索期间只隐藏列表，并在结果上方给「返回会话列表 · 保留筛选与位置」。
- **详情栏信息分层**。顶层只留标题、收藏、agent 与来源；完整会话信息与工作目录收进两个可展开区块，标签与备注上移；收藏从标签区的小链接移到标题行。恢复能力由阅读区底部统一说明（可恢复给动作，不可恢复给「此记录支持阅读、检索与导出」）。
- **备注草稿按会话保留**。编辑中途切走会话、再切回来不再丢失未保存的内容（仅在本次运行内保留）；保存回调按会话键判断，避免异步返回时把「备注已保存」写到现在正在看的另一个会话上。
- **设置里的阅读预览改用真实渲染器**（`ReadingPreview`），不再是一份手写的近似样式；快捷键表补 `Ctrl + F` 与 `Enter / Shift + Enter`；默认阅读位置的说明改为「首次打开或没有已记阅读位置时应用」。
- **单实例守卫**。`session.lock` 只回答「上次是否异常退出」，它是文件标记而不是所有权：第二个实例启动时发现 lock 存在就判定上次崩过，于是每次多开一个窗口都会亮一次崩溃横幅。改用命名互斥锁先回答「现在是否已有一个我」，已有实例时第二个进程直接退出，lock 从此只在真正的异常退出后残留。Windows 走 `CreateMutexW`；其他平台没有现成路径、单实例也不是核心需求，退化为不拦截。
- **选择文案收紧**。只在多选时显示批量操作条，单选时提示「正在阅读 · Ctrl / Shift 多选，右键查看单项操作」；全选按钮与读屏说明改为「全选筛选后当前展开项（包含屏幕外行）」——Ctrl+A 的作用域本就是筛选结果而不是屏幕上可见的那几行。

## 修复

- **索引事件载荷解码错误**。`EmitEvent(name, data...)` 只传一个参数时把该参数直接当作 `data`，传多个才是数组；Go 侧 `index:progress` / `index:ready` 都是单参数，前端却按 `data[0]` 取值，于是拿到 `undefined`——状态条永远停在「全文索引尚未就绪」，而事件丢了不报错，只表现为一直不更新。两种形状都收下。
- **第二次启动误报异常退出**（见上「单实例守卫」）。
- **删除预览的「将删除文件总大小」把元数据改写算作空间回收**。`state_5.sqlite` 等文件只删行或原地重写、文件大小不变，用户按这个数字预期磁盘释放会落空。文案改为「仅统计上述删除的文件」，并在元数据改写一项注明不改变其大小。

## 升级

关闭旧程序，运行 `AgentDeck-v0.3.0-win-x64.exe`。沿用现有本地数据目录，无数据库迁移、无数据清理；建议升级前在「设置」中创建完整备份。

**首次启动仍会重读全部会话**：旧索引库里没有 `doc_sources` 记录，任何会话都无法判定「没变」，因此这一趟等价于一次全量构建（与旧版本行为相同），结束时写回状态；从第二次启动起才走增量。索引库的 schema 新增一张表（`CREATE TABLE IF NOT EXISTS`），不需要重建，也不会动 `docs` 表里已有的正文。

若怀疑索引漏了内容（例如上游改写文件但大小与修改时间都没变），在「设置 → 索引」里点「重建索引」做一次整库重建。

## 已知限制与未执行项

- **增量判据是文件大小与修改时间**，不是内容哈希。上游只追加（Codex / Claude 历史会话的常态）时完全够用；若上游改写文件且大小与修改时间都没变，索引会漏掉这次更新——此时用「重建索引」。判据刻意保守：文件不存在、记录缺失、保留副本没有上游文件，一律按「变了」处理，只允许反方向的误判。
- **索引规模统计需要扫一遍 `docs` 表**（28 万行）。只在构建末尾做一次，统计失败不视为构建失败，退回这一趟的计数，数字偏保守。
- **备注草稿只在本次运行内保留**，不落盘；程序退出后未保存的草稿丢失。
- 本机 DPI 为 200%，未走查 125% / 150% 与深色模式下的新增界面。
- 未执行：真机上点击验证长代码块的展开与不限高两态；页末「继续阅读后续内容」与相邻窗口摘录的点击验证；备注「保存」的写路径（刻意未点，避免在真实标注库写入测试数据）；`Ctrl + A` 在会话列表中的真机行为确认（焦点不在列表时该组合会全选页面文本，未能区分是焦点问题还是缺陷；列表工具条的「全选」按钮已验证，结果为 25 项）；macOS / Linux 构建与运行；代码签名与安装包。
