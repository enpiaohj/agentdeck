# AgentDeck v0.18.0

发布日期：2026-11-12

## Added

- **ChatGPT 项目命名辅助**：官方导出不含项目名，只有 `g-p-` 开头的项目编号。导入页命名项目时按可靠程度提供线索，都不自动保存：
  - **桌面应用里的名称**：本机的 ChatGPT / Codex 桌面应用把项目列表连名字记在自己的状态文件里（`$CODEX_HOME` 或 `~/.codex` 下的
    `.codex-global-state.json`）。只读取其中的项目列表，读到就预填到输入框；没有安装、文件缺失或格式不认识时静默跳过。
  - **上传的文件名**：取自导出包里的 `library_files.json`，每个项目最多列出三个（新的在前，已删除和隐藏的不算），完全离线。
  - **推荐名**：根据项目里会话标题中反复出现的词推测（保留英文原来的大小写，过滤“如何”“创建”这类通用词）；标题不够时取上传文件名
    （跳过截图与时间戳这类名字）；会话只有一两个时取最近的标题；证据不足就不推荐。以按钮形式给出并说明依据，需要你点“使用推荐名”或
    “全部使用推荐名”才生效。
  - **在 ChatGPT 中打开**：每个项目一个按钮，用浏览器打开项目页面，页面上直接显示项目名。
- **“设置”>“常规”里可选择打开网页链接所用的浏览器**。用户常在某个特定浏览器里登录了 ChatGPT，而系统默认浏览器往往是别的
  （例如某个应用自带的浏览器）。下拉框列出本机已安装的浏览器，并标出系统默认、正在运行、窗口标题里有 ChatGPT 的（仅作提示：
  只看得到每个窗口当前的标签页，所以没有标记不说明什么）。选择会被记住。

## Changed

- 应用里所有打开网页的地方（官方导出说明、项目页面、会话正文里的链接、检查更新的发布页、关于页的链接）统一走同一个入口：
  设置里选了浏览器就用它；没有选择、所选浏览器在本机找不到或启动失败时，退回系统默认浏览器，链接总是打得开。
- 应用配置文件 `app-config.json` 新增可选字段 `browser`（浏览器 ID，空为系统默认）；改回默认时该键被移除。

## Security

- 打开链接：只接受 `http` / `https` 的绝对链接，拒绝 `file:`、`javascript:`、以 `-` 开头的参数、含空白或换行的字符串，长度上限 4096；
  链接作为单个参数交给浏览器，http(s) 不可能被浏览器读成它自己的选项。要启动的浏览器程序只能来自本机检测到的列表，
  前端传来的不是浏览器 ID 的取值会被拒绝，而不是悄悄当成“系统默认”保存。进程一律经 `internal/proc` 启动。
- 浏览器检测只读注册表里的浏览器列表与默认关联，并枚举可见窗口的所属程序与标题；标题只与“ChatGPT”比较，不保存、不记录。
  不读取任何浏览器的数据（配置文件、历史、Cookie、密码）。
- 桌面应用状态文件只读，且只解码项目列表与旧版项目表这两处，不读取其中其它字段；单测覆盖“文件内容不被改动”。
- 发布前 `govulncheck@v1.1.4` 与 `npm audit` 均为 0 项。

## Known Issues

- 推荐名只是推测，请确认后再用：在一份真实导出上，给出推荐的项目里约一半与真实名字相关，证据不足的项目不推荐。
- 浏览器检测只提示，无法判断哪个浏览器、哪个配置文件登录了 ChatGPT；同一浏览器有多个配置文件时，链接只会在它上次使用的那个里打开。
- 项目页面网址（`https://chatgpt.com/g/<项目编号>/project`）的格式来自第三方资料，未在 ChatGPT 账号上逐项验证；项目编号不是
  32 位十六进制时按钮置灰。
- 桌面应用的状态文件是应用内部格式，将来改版后可能读不到名称，届时静默退回手动命名与推荐名。
- 浏览器检测与启动只支持 Windows。
- 上一版（v0.17.0）的已知问题仍然存在：导出里图片文件名多为通用名、阅读区图片暂不支持点击放大、旧版导出的 Markdown 不被识别为
  同一会话、含大量图片的备份旧版无法恢复。
- 未在 macOS / Linux 上构建运行。

## 升级与回退

- 0.x 阶段不承诺配置与数据完全兼容。本版只新增一个可选配置字段，不改数据库结构，首次启动无需迁移。
- 升级：在应用内“检查更新”或手动用新 exe 替换即可。
- 回退：换回上一版 exe 即可。旧版读配置时会保留不认识的 `browser` 字段，之后再升级仍然生效。
