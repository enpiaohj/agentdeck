# AgentDeck v0.20.1

发布日期：2026-11-18

## Changed

- 按微软中文术语与风格统一界面文字：
  - “继续已清理的会话…”按钮改为“继续会话…”（它与普通的“继续会话”按钮不会同时出现）；右键菜单项改为“从保留的副本继续会话…”；对话框标题改为“继续会话”。
  - 两种继续方式改称“重建会话文件后继续”与“新建会话并附带历史记录”；对话框字段改为“原项目目录”“继续会话的目录”“将创建的会话文件”，复选框改为“完成后立即在终端中继续”。
  - 原始记录其实是被 Claude Code 删除的，所以“清理”改为“删除”；设置里的“保留期”改为“保留期限”，“快到期”改为“即将到期”，“调大”改为“增加”，“复制这一行”改为“复制此行”，“不要写 0”改为“请勿设置为 0”。
  - “带回”“转成文字”“新开”“接着聊”等口语改为“包含”“转换为文本”“新建”“继续”。
- 同类问题一并修正：界面与 README 里的“点击 / 点“…””改为“选择“…””或“单击”（更新页、侧栏、关于页、ChatGPT 导入页、提问导航条提示、会话列表的键鼠说明里的“Ctrl 点击”改为“Ctrl+单击”）；终端设置里的“新开一个窗口 / 标签”改为“打开一个新的窗口 / 标签”；ChatGPT 导入页的“带回已命名的项目”改为“保留已命名的项目名称”。
- 后端的几条错误提示同步改为书面表达，例如“此会话在 Claude Code 中仍然存在，可以直接继续，无需重建”。

## 说明

- 本版只有上面的文字调整，没有改动功能、数据格式或配置字段，也没有修复缺陷。按版本规范（`0.x.y` 只用于修复缺陷）它本应是 v0.21.0；这里按维护者的指定使用 v0.20.1。
- 保留未改的：“已清理 N 个旧批次”“已清理旧版本”确实是清理操作，用“清理”是准确的。

## Known Issues

- **构建工具链有一项尚无修复版本的高危公告（发布时的例外，已经维护者确认）**：`npm audit` 报告 `picomatch`（`<=4.0.7`，ReDoS，GHSA-fc5q-39xc-vjpf）经 `vite` → `fdir` / `tinyglobby` 传导，共 4 项高危。截至发布时 npm 上 `picomatch` 的最新版本就是 4.0.7，没有修复版本；npm 建议的“修复”是把 `vite` 降到 6.2.7，我在临时副本里验证过，降级后 `vite` 6.2.7 本身带有另一个高危公告，并不能消除问题，所以没有采用。影响范围：只有开发时的前端构建工具（`devDependencies`），不是运行时依赖；`npm audit --omit=dev`（生产依赖）为 0 项；已核对发布的 exe 和前端产物里都不含 `picomatch`。上游一发布修复版本就升级。
- 重建的会话不是原文件：工具调用的 id 配对、思考内容、消息 id 无法还原；很长的会话只保留开头与最近的部分。
- 只支持 Claude Code（`claude`）：Claude Desktop、WSL、网关与导入的会话不支持。
- 与 v0.20.0 相同：会话保留期的“到期”按文件修改时间和默认 30 天估算，只读取用户级 `settings.json`；原始会话里已经变成 `�` 的内容无法恢复；仅 Windows。
- 未在 macOS / Linux 上构建运行。

## 升级与回退

- 本版只改界面文字，不改数据库结构与配置字段，首次启动无需迁移。
- 升级：在应用内“检查更新”，或用新 exe 手动替换。
- 回退：换回上一版 exe 即可，数据与配置不受影响。
